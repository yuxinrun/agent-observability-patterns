# 阅读指南：30 分钟找到你要的那一章

这本手册解决一个非常具体的问题：**你的 Agent 上线了，但你看不见它。**

它不教你怎么让模型更聪明，也不比较哪个模型更强。它只教一件事：**怎么把一个会自己拿主意的程序，变成一条能看清、能度量、能追责、能优化的链路。**

## 这本书适合谁 {#audience}

| 角色 | 你会得到什么 | 建议起点 |
| --- | --- | --- |
| 零基础 AI 爱好者 | 一套能看懂的直觉和类比，不写代码也能读完 | 00 → 01 → 03 → 09 |
| 后端 / Agent 开发者 | 可直接复制的埋点代码与四种工程模式 | 13 → 02 → 08 |
| Agent 平台开发者 | 多租户、采样、存储、成本控制的完整设计 | 06 → 11 → 14 |
| SaaS 创业者 | 成本模型、SLO、告警与看板，能拿去和团队对齐 | 03 → 05 → 09 |
| 运维 / SRE | 告警降噪、采样、容量规划与故障排查流程 | 05 → 12 → 14 |

## 开始之前 {#prereq}

读代码章节需要：

- 会一点 Python（或 TypeScript），能看懂 `with` 和 `async`。
- 知道什么是 HTTP 请求头、什么是 JSON。
- 有一个能跑 Docker 的环境（跑 Demo 用）。

不需要：

- 不需要读过 OpenTelemetry 规范。
- 不需要用过 Langfuse / Jaeger / Grafana。
- 不需要懂分布式追踪的理论。

## 三条阅读路径 {#paths}

**路径 A：我只想搞懂它在干什么（2 小时）**

00 开篇 → 01 基础概念 → 03 指标 → 09 看板。读完你能和工程师对上话，也能判断一份看板设计得对不对。

**路径 B：我要动手埋点（半天）**

13 Demo → 02 追踪模式 → 08 埋点工程 → 12 踩坑。照着 Demo 跑通一条链路，再回头补模式与反模式。

**路径 C：我要负责上线（一天）**

06 平台选型 → 05 告警 → 11 安全合规 → 14 规模化。这四章决定了「能不能长期跑得起」。

## 30 分钟最小闭环 {#quickstart}

如果你想立刻看到东西，按这个顺序做：

```bash
# 1. 起一个本地后端
docker run -d --name jaeger -p 16686:16686 -p 4318:4318 \
  jaegertracing/all-in-one:latest

# 2. 装依赖
pip install opentelemetry-sdk opentelemetry-exporter-otlp-proto-http

# 3. 跑第 13 章的第一个 Demo
python demo_otel.py

# 4. 打开 http://localhost:16686
```

看到瀑布图之后，再回来看 [第 02 章](/traces/)，你会有完全不同的感受。

## 本书的约定 {#conventions}

- **人话翻译**：每节的 `tip` 框是给非工程的解释，可以跳过。
- **注意 / 危险**：前者是「你可能会踩」，后者是「踩了会出事」。
- **代码块**：都可以直接运行，除了明确标注「伪代码」的部分。
- **指标名**：统一使用 `gen_ai.*` 与少量自定义前缀（`agent.`、`tool.`、`memory.`、`cost.`）。
- **图**：全部手写 SVG/CSS，没有截图，缩放不失真。

## 这本书不做什么 {#not}

- 不比较模型能力，也不推荐模型。
- 不教你写 Prompt（那是 better-agent 的事）。
- 不提供厂商报价，只给成本模型和计算方式。
- 不保证所有 Demo 在你的环境一次跑通——但每个都标了常见卡点。
